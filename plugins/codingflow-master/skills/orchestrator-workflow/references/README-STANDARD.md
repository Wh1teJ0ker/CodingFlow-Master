# 项目 README 编写标准

## 1. 目的与适用范围

本标准用于创建或审查目标项目根目录中的双语 README。目标是让首次访问者在最短时间内知道三件事：**项目是什么、当前是否可用、如何快速上手**。

本标准区分三类内容：

- **规范**：本文件，定义项目 README 必须满足的要求。
- **模板**：`../../assets/templates/README.md.template` 与 `README_EN.md.template`，提供可复制结构。
- **实例**：目标项目中的 `README.md` 与 `README_EN.md`，只记录该项目当前可验证的事实。

README 是 GitHub 仓库首页入口文档，不是完整产品手册。能放到 `docs/` 的长说明，不强制塞进 README。

## 2. 双语文件与互链

目标项目必须同时提供：

- `README.md`：中文主版。
- `README_EN.md`：英文版。

两个文件必须在主标题后提供清晰的相对路径互链：

```markdown
[English](./README_EN.md)
```

```markdown
[中文](./README.md)
```

双语版本至少保持以下事实一致：

- 项目定位与一句话说明；
- Quick Start 命令；
- 基本验证方式；
- Release / License / 安全反馈等必要链接。

翻译可以按语言习惯调整表达，但不得改变事实。

## 3. 必需内容（轻量版）

README 必须覆盖以下内容，章节名称可按项目类型小幅调整。

### 3.1 项目介绍

用一至三句话说明：

- 项目解决什么问题；
- 面向哪些用户或场景；
- 当前边界是什么。

避免“最佳”“完整”“生产就绪”等无法验证的表述。

### 3.2 Quick Start

这是 README 的核心部分。必须提供从干净环境开始的最短可重复路径，通常包括：

1. 获取源码；
2. 安装依赖；
3. 配置本地环境（如需要）；
4. 启动或运行；
5. 最基本的验证命令。

涉及密钥时只引用环境变量名或示例文件，绝不展示真实凭据。

### 3.3 基本验证方式

列出项目实际支持的最小验证命令，例如：

- 测试；
- lint / typecheck；
- 最小启动或构建验证。

未在干净环境验证的命令必须标注。

### 3.4 必要链接

README 末尾至少给出当前项目真实存在的必要链接或说明：

- Release 下载位置，或“当前无公开发布产物”；
- License 文件；
- 安全问题反馈方式（如公开仓库不适合披露细节，也要写明反馈渠道）。

## 4. 可选内容

以下内容按项目需要添加，不再作为强制项：

- 功能列表；
- 截图或演示；
- 技术栈；
- 环境要求细表；
- 构建说明；
- 路线图；
- 贡献指南摘要；
- 隐私与安全的展开说明；
- 已知限制明细。

原则：如果这些内容会明显帮助首次使用者，就写；否则放到 `docs/` 或独立文档中。

## 5. GitHub 仓库首页写法要求

- 标题下方优先放一句话说明，不要先堆长段背景。
- Quick Start 应尽量在前半部分出现。
- 长 README 可以加目录，但轻量 README 不强制。
- 可以放 badge，但只保留对用户有实际判断价值的 badge，不堆砌。
- 若项目有 `docs/`、Release 页面、更新日志、Issue/Discussion/Security 页面，可在 README 中给出简洁入口。
- 不要让 README 首页变成开发日志、会议纪要或内部流程记录。

## 6. 占位符规则

模板只允许使用描述性通用占位符，推荐格式为：

```text
{{PROJECT_NAME}}
{{ONE_LINE_DESCRIPTION}}
{{QUICK_START_COMMAND}}
{{VERIFY_COMMAND}}
```

要求：

- 使用大写英文与下划线，含义唯一；
- 不包含真实组织名、产品名、用户名、域名、绝对路径或版本承诺；
- 命令占位符必须替换后才能发布；
- 不适用内容应删除或改成真实说明，而不是保留空占位符；
- 发布前搜索 `{{` 和 `}}`，确保无残留。

## 7. 状态与证据要求

README 中的完成态声明必须有仓库内证据支持：

| 声明 | 最低证据 |
|---|---|
| 可运行 | Quick Start 命令可复现 |
| 已发布 | 存在真实 Release 页面或下载条目 |
| 支持某平台 | 有构建/测试证据或维护者验证记录 |
| 已验证 | 对应验证命令已实际运行 |

无法提供证据时，应降级为“实验性”“未验证”“计划中”或“未发布”。

## 8. 何时必须同步 README

以下变化发生后，README 必须同步：

- 项目定位变化；
- Quick Start 命令变化（含涉及的环境或平台变化）；
- 启动/安装/配置方式变化；
- 当前版本、发布入口或下载方式变化；
- 关键限制或安全反馈方式变化。

## 9. 发布前检查

- [ ] 中英文文件存在且互链。
- [ ] 项目介绍、Quick Start、验证命令在双语版本中一致。
- [ ] Quick Start 命令已实际运行，或明确标注未验证。
- [ ] 必要链接真实存在；如不存在，已写明当前无公开产物或暂无对应入口。
- [ ] 不含凭据、私有地址、个人绝对路径或项目外身份信息。
- [ ] 搜索确认不存在未替换的 `{{PLACEHOLDER}}`。
