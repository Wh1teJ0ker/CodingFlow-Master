# /audit

用户执行 `/audit` 触发 Phase 0 的仓库审计部分（不启动任务拆分）。

## 执行步骤

1. **代码结构审计**：
   - 读取项目根目录结构
   - 识别技术栈（读取项目清单文件、构建配置等）
   - 识别源代码目录布局
   - 识别测试结构和 CI/构建配置

2. **已有文档审计**：
   - 检查 `docs/` 是否存在，内容是否与代码一致
   - 检查 `README.md` 是否存在，是否反映项目真实状态
   - 检查是否有版本管理文档

3. **Git 历史审计**：
   - 查看最近提交（`git log --oneline -20`）
   - 识别当前分支和版本 tag（`git tag`）

4. **代码质量速览**：
   - 扫描模块边界、依赖方向、错误处理
   - 参考 `skills/orchestrator-workflow/references/CODE-STANDARD.md`

5. **构建或规范化 `docs/`**：
   - `docs/` 不存在 → 从零创建文档体系
   - `docs/` 不完整 → 补全缺失文档，修正不一致
   - `docs/` 完整 → 仅做增量更新

6. **输出审计摘要**：向用户报告项目状态、文档完整度、代码质量速览、发现的问题

## 注意

- 审计必须基于实际文件和命令输出，不基于对话记忆
- 不启动任务拆分（如需拆任务请用 `/plan`）
- 文档描述不能比代码更乐观
